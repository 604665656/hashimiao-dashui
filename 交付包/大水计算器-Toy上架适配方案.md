# 大水计算器 · Toy 上架适配方案

> 前置事实：本项目在 **B站 Toy** 上架，平台提供云存档与分数榜；同时仍要保留「一个 HTML 拷走就能玩」。
> **落地状态（2026-11-12）**：已写入 `大水计算器-合并版.html`。14 组无头浏览器用例全过，0 发现项、0 控制台错误；适配层增量 23.1 KiB，产物 833.3 KiB，仍是零 CDN 单文件。

## 要解决什么

调研报告初版把「无后端、不上传」当成唯一部署形态，把云存档、跨设备同步、跨用户榜一并判成「不成立」。但 Toy 的能力由**平台**提供，不是自建后端，所以结论要按形态分叉：

| | A · 本地单文件版 | B · Toy 上架版 |
|---|---|---|
| 存档 | `localStorage`，零上传 | 平台云存档 + 本地镜像，冲突时重读 |
| 榜单 | 本机多档案榜 | 平台分数榜 + 本机档案榜双轨 |
| 身份 | 本机档案名 | 平台用户资料，不自建账号 |
| 降级 | —— | SDK 未就绪 / 未授权 / 报错 → 静默回退本地 |

目标只有一句话：**同一个 HTML，本地双击完全离线可玩；放进 Toy 容器自动获得云存档与平台榜，且敏感数据永不上云。**

## 怎么做的

### 1. 能力探测 + 自动降级

```
TOY = window.toy || (studio.sdk && studio.sdk.toy) || null
TOY && TOY.available() && await toy.ready()   // 带超时，别卡启动
```

SDK 未就绪（"toy id not available on host"）做透明退避重试；开发 / 预览态用 Mock，不发真实 RPC。[22] 所有平台调用包一层 `safe()`：超时、拒绝、异常都返回 `null`，界面不弹错误、玩法不中断。

把存档收敛成一个接口，业务代码只认它：

```
Store.get() / Store.set(patch) / Store.merge(remote)
  ├─ 本地实现：localStorage（永远可用，唯一真源之一）
  └─ 云端实现：仅 TOY 可用时挂载，异步、按事件触发
```

「网络调用只在**读档 / 结算 / 保存**这类业务事件发生」，不要每帧或每次点击都写云。[23]

### 2. 云档只放最小可重建摘要

按 1 KB / 项保守分片（B站小游戏开放数据接口规定 128 个 KV 上限、key+value ≤ 1 KB、key ≤ 128 字节，且需 `order` 字段；**Toy 网页部署形态的配额未核实**，按更紧的做不会错）。[20]

```json
{
  "schema": 2,
  "app": "dashui",
  "savedAt": 1731340800000,
  "profile": { "name": "本机档案", "avatar": "cat" },
  "settings": { "goal": 1700, "interval": 30, "cooldown": 30,
                "sound": false, "bgm": false, "volume": 0.35, "bgmTrack": "轻快" },
  "days": {
    "2026-11-12": {
      "ml": 1250, "valid": 3, "cheat": 1, "milk": 1,
      "achievedAt": 1731340000000, "score": 63,
      "auditHead": "a1b2c3…", "auditLen": 4,
      "mood": "通透", "rank": "B"
    }
  },
  "unlocked": { "ends": ["S","B"], "cgs": ["01_候机"] },
  "hydrationIndex": 72,
  "checksum": "sha256…"
}
```

**上云白名单**：schema 版本、每日流水摘要（量 / 时间 / 来源 / 审计哈希头）、积分与结算成绩、Rank / CG 解锁 **id**、形象选择、心情枚举、设置、水合指数、校验和。

**永不上云**：奶茶抓拍照片（base64 大且敏感）、OpenAI 兼容接口 Key、精确 GPS 经纬度（最多留省市区名称且需同意）、通知 / 摄像头授权状态、完整语录上下文。照片与完整流水始终留本机——云档丢了能重建进度，但**不能重建照片**，这点要写进界面说明。

### 3. 读档冲突策略

```
启动 → 读本地镜像 → 若 TOY 可用，异步读云档
  云档空 / 校验失败 / 超时 → 保留本地，不覆盖
  云档与本地都有效 → 比对 savedAt + checksum
    一致 → 合并解锁 id（取并集）
    冲突 → 重新读取一次；仍冲突则进「恢复向导」让用户选 合并 / 用云端 / 用本地
```

**绝不自动以空存档覆盖本地**。取消请求不等于撤销已发出的写入，超时也不能证明云端没提交；结果未确认时一律重读后继续。[23] 平台接口未见版本比较写入（CAS），多设备同时编辑会互相覆盖，界面提示「单设备编辑」，并用双代索引 + 校验和做冲突检测（第三方项目实践，未核实）。

### 4. 平台分数榜双轨

- 结算时 `rank.submit` 只提交三个数：**总分 / 达标时刻 / 规则版本**，不传饮水明细、天气、定位、心情原文。
- 首次参加榜单需玩家点击并经过平台授权；缓存 `rank.list()`，只在结算 / 保存时写入，遇限流做指数退避，不写死共享配额（第三方项目实践，未核实）。
- 平台榜是**客户端休闲成绩展示，无服务器反作弊**。卡面与文案不得写「官方认证」，要写「平台成绩 + 本机审计摘要」。
- 本机档案榜保留：断网、降级、未授权时仍能看到自己的今日榜 / 历史总榜。

### 5. 界面与打包

- HUD 加一枚小标签：`本地档案` / `云存档` / `降级中（已存本机）`，点击进「存档状态」面板，展示来源、最后同步时间、云档校验和、导出镜像按钮。
- 分享卡按形态切一行说明（本地版「本机校验码」；Toy 版「平台成绩 + 本机审计摘要」）。
- 打包：Toy 按扩展名白名单打包，`.html/.css/.js/.json/.webp/.ogg` 等允许，白名单外文件直接导致打包失败。[21] 本项目 61 张 WebP + 4 段 ogg 全是 HTML 内 data URI，最终**只有一个 `.html`**，天然合规，不必拆资源目录。
- 摄像头抓拍：Toy 版若改用平台提供的摄像头能力，仍默认关闭、拍完即停流、照片不进云档。

**实测汇总**：14 组用例全过，**0 发现项、0 控制台错误**。关键结果：本地形态 `mode=local / on=false` 且榜单只有 2 个 tab；Toy 形态 `mode=cloud / kind=toy`，第三个平台榜 tab 正常，结算提交 `{score, extra:{at, rule:2}}`；SDK 未就绪在 2 秒内降级且喝水不受影响；写入超时后本机 500ml 与标记都完好；损坏 / 空云档一律不覆盖本地；冲突重读后弹三选一，「合并」把 `B/S/A/C` 与两张 CG 取并集；「用云端」后本地照片、`llm`、`location` 仍在；云载荷键集合不含任何敏感字段。

**一处偏差（如实记录）**：⑨ 适配层增量实测 **23.1 KiB**，高于方案写的 `<20 KiB`。超出来自冲突重读、敏感键名审计、恢复向导三选一，以及顺手修的凌晨文案。没有新增任何位图或音频，总文件 833.3 KiB 仍远低于 1 MiB 预算。不为凑数字删逻辑，按偏差留档。

## 坑

1. **两套口径别混**：`bl.setUserCloudStorage` 的 128 KV / 1 KB 限制来自「哔哩哔哩小程序·小游戏开放数据接口」，不是 Toy 网页部署的官方配额；Toy 侧配额本次未核实。按 1 KB 分片是保守设计，不是平台事实。
2. **「结果未确认」不是「没写入」**：取消、超时、断网都不能当成云端失败，读档必须重读；否则会用空档把本地进度抹掉。[23]
3. **没有 CAS**：平台接口未见版本比较写入，多设备同时编辑会互相覆盖；产品层要提示单设备编辑，别假装有自动合并。
4. **host not ready 竞态**：页面启动早于 SDK 注入，`toy.ready()` 要带超时与透明退避，不能让整个游戏卡在等待。[22]
5. **平台榜 ≠ 反作弊**：分数是客户端提交的，30 分钟冷却和审计哈希只在本机成立；卡面必须写清「休闲成绩展示」，别把本机校验码包装成官方认证。
6. **首次授权要用户手势**：榜单击一次才授权，别在启动流程里静默调用；缓存榜单、只在结算 / 保存写入，避免限流。
7. **白名单是按扩展名查的**：把内嵌资源拆成外部 `.bin` / `.dat` 会直接打包失败；本项目保持全内嵌反而最省事。[21]
8. **照片上云是隐私红线**：Toy SDK 虽列有摄像头能力，但抓拍照片、API Key、精确坐标一律只留本机，与是否上架无关。
9. **报告结论要带形态前缀**：以后写「不成立」必须写明是「纯本地形态」还是「Toy 形态」，否则又会像初版一样把平台能力误判成应放弃。

### 落地时额外踩的 4 个坑

1. **事件处理器是「值拷贝」**：script0 里写死过 `$('#btnBoard').onclick=openBoard`。在第三个 script 里重新赋值 `openBoard` 对已绑定的处理器无效，点按钮走的还是旧函数，平台榜 tab 点了没反应。`leaderboardHTML` 因为是运行时动态查找所以正常。改成包装 `bindBoard`（每次开榜都会动态调用）＋把按钮引用重绑到新函数，并用 capture 阶段 `stopPropagation` 截断原 `onclick`。
2. **平台榜无限微任务链**：初版 `renderToyBoard()` 末尾调 `toyRankLoad().then(renderToyBoard)`，重绘又发起新拉取，`.then` 再重绘……主线程被微任务占满，Playwright 点击直接挂起。拆成「拉取只拉、渲染只渲染」，只在用户手势处显式 `toyBoardRefresh(root)` 一次，并加 `_rankLoading` 防并发。
3. **测试 seed 被自动云写入覆盖**：用例想预置一份损坏 / 冲突云档，但页面首次加载的空档分支会在 1.5 秒后自动写一份合法档，把 seed 冲掉，导致「损坏档被接受」「合并不到解锁」两个误报。改成 `addInitScript` 里同步预置（用与页面一致的 FNV 哈希，走 `toyVerify` 的二次比对），并给 Mock 加 `__toyFreeze` 禁止自动写覆盖。
4. **降级等待太久**：初版 SDK 未就绪要等 3000+2000ms 才降级，启动被拖到 5 秒，测试等 2.2 秒时还停在初始态。缩到 1200+800ms，2 秒内完成降级，玩法不中断。

### 云档后续增补（P0 链路落地后）

`toySnapshot()` 的每日摘要新增两个字段，仍属最小可重建摘要、不破坏 schema 2 兼容：

- `auditHead` 从「id 拼接校验码」改为**同步哈希链的链头**（与分享卡、HUD 同一来源）；
- `auditOK` 标记该日链是否完整，冲突时在存档面板可见；
- `hydrationIndex` 从固定 0 改为实时计算值，另带 `hiBest / hiTickets` 便于跨设备重建成长状态。

抓拍照片、API Key、精确坐标仍**永不上云**；`toySensitiveAudit()` 改为只递归收集**键名**比对黑名单，避免用户档案名含 `lat` / `key` 之类被误判而跳过云写入。

### 与「本机镜像」的分工（P1 落地后补记）

数据 / 凭证中心的 `makeBackup()` 导出的是**完整本机镜像**（含抓拍照片、API Key、完整流水），与 Toy 云档的最小摘要是两条独立路径：

| | 本机镜像 JSON | Toy 云档 |
|---|---|---|
| 用途 | 误删恢复、跨浏览器迁移、离线备份 | 平台内跨会话续玩 |
| 照片 / API Key | ✅ 包含（用户自行保管） | ❌ 永不上云 |
| 完整流水 | ✅ 包含 | ❌ 只有摘要与审计链头 |
| 触发 | 用户手动导出 / 导入 | SDK 就绪后自动排队 |

云档冲突时的「恢复向导」仍以云端摘要为准；导入本机镜像时先预览差异再选合并 / 替换 / 新建，且替换与新建都留 5 分钟撤销窗口。两者互不覆盖：镜像导入不会自动写云，云档回读也不会删本地照片。
